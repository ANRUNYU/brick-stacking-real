# D2-01 多积木场景与任务规划

本任务对应 M4，使用仓库已有的 `SceneBlock`、`SceneSnapshot` 和槽位模型完成离线验证。M3 实机闭环及 B/C 联调待接入。

## 接入方式

使用 `SceneManager(slots, supply_match_distance_m=...)` 初始化一轮任务。B 提供当前帧的候选和颜色，C 提供统一坐标系下的积木中心及槽位依赖。调用方将已定位的供料候选组成 `SceneSnapshot`，传给 `manager.update_supply(observation)`，再把返回的快照交给 `choose_task(snapshot, manager)`。已知持物、已放置物体和未定位候选应由调用方排除在供料候选之外。

- 候选 ID 只在帧内使用。D 按坐标系、颜色和明确配置的米制距离做一对一关联。调度和槽位事务使用 D 分配的 `block_id`。
- 缺失的实体保留 ID 并标为不可见。在原位置附近重新出现且能唯一匹配时恢复可用。无法区分的同色轨迹锁定为歧义，该轮不再调度；存在未匹配旧实体时，也不为同色远处候选分配新 ID。
- ID 在同一 SceneManager 任务轮次内有效。观测必须来自同一来源、时钟域和 epoch，且时间戳严格递增。关联假设相邻可见位置的变化在距离窗口内；仅靠位置与颜色无法识别两次观测之间未被看到的同色互换。

槽位依赖允许任意输入顺序，初始化时拒绝缺失支撑和环。调度优先完成最低未验证层，并仅选择颜色和坐标系匹配、未占用的可见积木。四层配置对应红 4、黄 3、蓝 2、绿 1。上层槽位只有在所有支撑槽位均为 `PLACED_VERIFIED` 时才就绪。

事务按 `reserve`、`mark_unverified`、`commit_verified` 推进。只有调用方取得放置复检证据后才可调用 `commit_verified`。同一积木与同一槽位各只能归属一笔事务，预占检查和写入串行化。取物前取消可释放预占，已进入待复检状态的槽位保留占用。

## 离线验证

```text
python -m pytest -q tests/unit/planning/test_multi_block_scene.py
python -m pytest -q
```

用例覆盖同色身份、候选换序、遮挡、关联歧义、旧帧与 epoch 变化、支撑门控、同块和同槽竞争，以及完整十块颜色顺序。测试使用合成样例。
