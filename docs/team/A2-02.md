# A2-02 控制异常与恢复入口

在 A1-04/A2-01 的 Mock 路径注入反馈超时、许可或轨迹过期、传输断连及停止请求失败。异常结束当前命令，冻结整段序列，后续 `step()` 只返回终态。`MockArm` 可配置 `feedback_timeout_s`，从最后一个目标发出后计时，许可与轨迹截止时间仍独立生效。

`MockArm.get_execution_fault(command_id)` 和 `MultiSegmentRun.progress().fault` 提供 `TIMEOUT`、`EXPIRED` 或 `DISCONNECTED` 以及 `StopResult`。尚未调度时不请求停止。Mock 连接可用时可记录停止请求，确认停车与保持能力仍分别为 `false` 和 `null`。断连或停止请求失败时保留未确认原因。旧执行器的传输故障锁存，需新建恢复会话。

恢复调用方用当前观测位置新建 `MockRecoverySession`，调用 `observe()` 取得新 epoch 的状态，再按该状态重新规划并获取逐段许可。调用 `start(state["sample_id"], new_plan, new_permits)` 创建新的待执行序列。入口只接受当前会话最新且未过期的观察 ID，每个会话只发出一个序列。规划方负责将新计划与该观察关联。新会话从空命令队列启动，旧命令 ID、执行快照和队列均不用于恢复。进程退出后的现场设备状态仍须重新观测。

运行 `python -m pytest tests/arm` 检查故障注入、终态、停止请求语义及模拟重启后重新规划。真实故障试验与设备 StopPolicy 仍依赖 A1-03 现场证据及 M3 联调。
