# D1-04 单块 Mock FSM 与 SafetyGate

对应 M1，依赖 [D1-01 的 M0 契约](D1-01.md)。`PickPlaceFSM` 复用仓库现有的离线执行循环、场景事务和复检逻辑，要求一个空槽位。流程包括观察、选取目标、抓起复检、搬运、放置复检和稳定性检查。抓取失败后，仅在新观测确认积木仍在供料区且手为空时重试，达到配置上限后安全退出。

## 接口与门控

构造时传入 mock port、单槽位 `SceneManager`、事件接收器、预期设备 ID、标定哈希和任务超时。通过 `evidence_for(StepRequest)` 接入生产者的 Mock 或测试样例。请求提供阶段、积木 ID、槽位 ID、当前场景版本和配置哈希。回调返回该阶段的 `StepEvidence`，包含 A 的状态、C 的轨迹摘要及对配置标定的有效性判断，以及绑定当前上下文的短期许可。场景版本使用最近一次观测 ID。

每次分派前都校验观测和反馈的新鲜度、设备与时钟身份、标定状态和许可。许可关联设备、轨迹、配置、标定和场景版本，有效期必须落在当前离线新鲜度窗口内。Mock 的反馈时间和许可时间使用同一个合成时钟。任务超时单独使用主机单调时钟，在观察前后和分派前检查。Mock port 与证据回调应自行限制单次调用耗时，因为这个同步流程无法中断尚未返回的调用。

门控失败进入 `SAFE_HALT` 并记录原因。若抓起后许可失效，保留持物状态，流程不自动撤退或释放。阶段与动作分派记录包含场景、反馈、轨迹及版本信息。单个 FSM 实例只运行一次。现有十块 Mock 入口仍使用原来的执行流程。

## 离线复现

```text
python -m pytest -q tests/e2e/test_single_block_fsm.py
python -m pytest -q
```

单块测试使用现有 `MockTaskWorld` 和独立测试夹具，覆盖正常流程、重观察重试、超时、抓取耗尽、放置偏差、反馈过期、标定无效或未知，以及许可缺失、过期、过长或上下文不符。真机执行和真实证据接入属于后续联调。
