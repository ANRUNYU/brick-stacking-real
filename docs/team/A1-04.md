# A1-04 轨迹执行及结果反馈（M2a）

基于 A1-02 的 `brick_stacking.arm.adapter`。现有仓库未找到 C 的七轴轨迹样例，离线验收使用 M0 契约构造的七轴轨迹。

- `execute_trajectory(trajectory, permit, valid_until_host_monotonic_s=...)` 验证许可绑定和截止时间后返回命令 ID。对接 `PlanResult` 时由调用方传入计划的 `valid_until_host_monotonic_s`，轨迹结构本身没有截止字段。截止时刻视为已过期。
- `get_execution_status(command_id)` 和 `get_execution_result(command_id)` 查询当前命令，不推进执行。`step(command_id)` 推进 Mock，并在等待最终反馈时继续检查截止时间。
- `cancel(command_id)` 终止当前 Mock 命令。取消后不会应用后续轨迹点，也不会因迟到反馈转为成功。

发送最后一个目标后仍为 `RUNNING`，直到收到同设备、同 epoch、同单调时钟域的有效反馈。外部注入的反馈时间必须晚于最后目标的发送时刻，且处于配置的最大样本年龄内、未重复。七轴误差全部满足容差后才记 `SUCCEEDED`，结果保留用于判定的反馈。缺失、无效或未到位的反馈可在截止前重试，过期后记 `FAILED`。

默认反馈来自 Mock 关节读回。离线集成测试可在构造 `MockArm` 时传入 `feedback_reader`，模拟缺失、延迟或未到位的反馈。回调在 `step` 中同步调用，应及时返回且不能回调同一执行器。`max_feedback_age_s` 和 `goal_tolerance_rad` 的默认值只适用于 Mock。真机执行与实测到位验收仍依赖 M2 运动链和 A1-03 现场验证。

运行 `python -m pytest tests/arm` 验证接口、反馈门控、到位判定、过期和取消。
