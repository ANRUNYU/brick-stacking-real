# A2-01 多层连续执行与时间统计（M4/M5）

`brick_stacking.arm.sequence.MultiSegmentRun` 接受 A1-04 的 `MockArm`、M0 `PlanResult` 和按段排列的 `Permit`。初始化时传入七轴弧度限位与起点反馈最大年龄。使用手动时钟回放时，执行器和 `MockArm` 共享同一个时钟。一次运行独占该 Mock 实例。

```python
from brick_stacking.arm.sequence import MultiSegmentRun

run = MultiSegmentRun(
    arm, plan, permits, joint_limits_rad=joint_limits_rad,
    max_state_age_s=max_state_age_s,
)
progress = run.step()   # 调度当前段并推进已到时的点
snapshot = run.progress()  # 查询状态，不调度
# run.cancel() 可在首段前、段内或段间终止整个序列。
```

启动前校验整份计划的轨迹、限位和逐段许可绑定。每段开始时重读起点反馈，检查设备身份、时钟、epoch、年龄和实际位置，并重新检查计划和许可是否过期。运行中沿用 A1-04 的到位判定，同时检查反馈位置限位。只有前一段成功后，下次 `step()` 才会尝试下一段。取消或失败后，后续 `step()` 只返回终态。

统计包含已完成段数、总段数、各已调度段的 phase、命令 ID、状态和耗时。总耗时从首次 `step()` 到终态，包含段间等待。分段耗时从该段命令启动到终态。首段启动前取消时总耗时为零。

`python -m pytest tests/arm/test_sequence.py` 用三层 Mock 轨迹验证连续执行、进度和耗时，以及段间失效、反馈越界和取消。现有工作区未找到 M3 多层轨迹样例，测试使用按 M0 契约构造的七轴数据。真机限位、碰撞及多层连续执行仍待 M5 联调。
