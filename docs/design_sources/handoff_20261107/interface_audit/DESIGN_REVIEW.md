# 真机开发计划审查与建议 v0.3
日期：2026-11-07。本文是对用户提供 v0.2 设计的增补评审，不替换原稿，不执行其中的开发模板或启动指令。

## 1. 结论

v0.2 的先单臂、头部优先、抓后/放后验证、有界恢复、统一坐标和独立真机工程方向适合继续保留。当前应先补齐身份注册、普通用户相机权限、真实型号配置和停止策略，再做单臂闭环。没有必要为了“用到全部设备”先实现双臂交接、三机全帧融合或完整 ROS 消息生态。

接口存在已证实，但四个腕关节卡顿、相机近距离深度质量、外参和 TCP、全机碰撞、安全停止均未验收；这些是动作阶段的门槛，不能因为暂缓修复 J6/J7 而从后续验收中删除。

## 4. 优化后的开发顺序与退出标准

### M0A 接口与配置注册（本轮完成主要发现部分）

交付本接口文档、原始 JSON 和只读探针。追加现场遮挡已确认三台相机角色。剩余：实体线缆标签、双臂关节方向/编号铭牌；普通用户相机访问；重插重启后的身份拒绝测试。不能把当前 can 名称永久写死后直接执行。

### M0B 安全与控制能力验收（真实动作之前）

分别确认前五轴、V2腕轴、O6 的急停、撤销命令、保持/解除保持和失联后行为。外部有独立急停和现场监护；软件测试先在 Mock 中注入超时，不能用切真实心跳做未经评估的故障实验。J6/J7 的跟踪、低速误差与静止稳定性进入这一阶段。

交付：StopPolicy、真实限位/零位来源、反馈频率与最大时延、控制器唯一所有权、轨迹中止结果；任何未知不能返回笼统“stop成功”。

### M1 感知与坐标准备（可与 M0B 的非动作工作独立推进）

先头部相机收录真实木块，覆盖四色、同色紧贴、遮挡、漆面反光。模型简单到能可靠验收即可：颜色+桌面平面+几何+多帧；分不清返回 AMBIGUOUS。离线锁定样本集，记录错误与拒绝率。

仅先实现一台相机的标定/反投影链，建立 mm 误差预算：感知、RGB-D 配准、头到world、base安装、TCP、持物偏移分别测量；不能只报像素重投影误差。腕部先用 RGB 是否可见来判断精定位价值，再要求可靠深度；不要假设近距离深度一定可用。

### M2 单臂单块闭环

先固定供料/放置区域、单色单块、一个已标定抓取姿态，完成 approach/grasp/lift/place/retract/verify。确认没有物理上无法完成的观察/接近姿态后，再扩展随机位置、四色和相邻实例。

以实际抓取持物成功、释放后稳定和 mm 偏差验收，不以运动 API 返回值通过。每轮保留失败类别、人工介入、首次成功率、最终成功率、P95耗时；成功率要有样本数与区间，不用单次演示当可靠性证明。

### M3 单臂完成10块与恢复

先完整结构，再追加复杂供料条件。将块尺寸作为实测输入，把槽位、接触面、支撑覆盖与相邻碰撞分开建模。倒塌后撤销受影响槽位的 verified 状态，重扫受影响区域，不一概重启整场，也不继续相信旧支持关系。

给每次恢复分配剩余时间与风险预算，达到上限后按完整规则允许的方式结束/跳过。颜色不符的降级策略独立配置，默认禁用，不能牺牲结构稳定性。

### M4 腕部精定位与第二臂

先证明腕相机能改善放置或抓取误差，再接入闭环微调。腕部时间同步未完成前，采用“停稳—采集—校验—小步”的离散观测，不做运动中视觉伺服；停稳时序也要经反馈验证。

先做左右臂直达可达性图；若单臂可完成任务，双臂只作为有数据支持的吞吐优化。需要转运时先用桌面中转位串行放取；增加一次抓放的代价必须纳入成功率与耗时比较。

### M5 并发与比赛压力测试

三相机同开、网卡吞吐、CPU/USB长测、图像过期/时钟重置检测、两臂共享区互斥、全机碰撞及整场无人工试跑。不能用三次单机取流替代并发验收。

## 5. 需要加入的工程契约

1. **启动自检 fail-closed**：SN/总线/协议/配置hash匹配，标定有效，新鲜反馈与明确安全状态齐备，才允许动作。识别成功和动作许可分开。
2. **时间契约**：记录设备时间、主机接收时间、时钟域和 epoch；发现相机/电机进程重启后旧 TF 不再有效。图像、关节和场景 stale 阈值按实测时延确定。
3. **命令契约**：有界队列、超时、取消、实际完成判据与 command_id。异常后丢弃过期路径，恢复时重新观察并重规划，避免重发旧积木目标。
4. **资源互斥**：每条 CAN 的命令所有者、每只手/臂、被抓块、槽位与共享空间均有所有权。lease 过期不能自动认为实体空间已空。
5. **抓取/接触判据**：没有可靠力/触觉时，不得以固定下降高度推断已经接触。组合视觉、几何、到位/电流等已验收信息；无法判断时拒绝释放或结束该尝试。
6. **配置来源**：实测、厂商源码、团队提供、建议值逐项标注。任何未来未绑定相机、未测限速/外参保持 null；不能靠“默认值”通过门控。
7. **数据与版本**：固定 SDK 实际文件hash；维护 raw_u8/percent/rad 的显式类型，分辨率变化使内参配置失效；比赛日志中不存 SSH 密码。
8. **测试范围**：Mock验证逻辑，录包验证感知，实机验证能力，各自报告来源。此次不扩展为新工程代码实现。
