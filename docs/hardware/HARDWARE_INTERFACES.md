### 3.1 底层读取协议与控制接口

- J1–J5：标准 CAN ID=电机 ID；单字节 0x06 读位置，0x2B 读使能位，0x5F 读温度；位置/温度响应的命令字后为 little-endian float32。位置单位 rad。存在 set_angle、set_velocity、set_acceleration、enable、disable、calibrate_zero，但本次只核验源码，没有调用控制方法。
- J6/J7：P-T-M 模式，目标角度 16 bit，速度/Kp/Kd/扭矩各 12 bit；不含与前五轴相同的内部轨迹生成器。
- J6/J7 模式读取：请求 ID=0x600+motor_id，载荷 67 0B 00 00 00 00 04 76；回应校验 ID、motor_id、index 后解析 little-endian int32，四个均为 2。
- 固定 SDK 默认量程：theta ±12.5 rad、速度 ±10 rad/s、Kp 0–250、Kd 0–50、扭矩 ±50 Nm。实际驱动器量程未读回；禁止据此宣称实际增益和扭矩换算已验收。
- MotorV2.set_velocity 只缓存；set_acceleration 只缓存，set_deceleration 无实际操作。平滑轨迹需主机持续发送。
- MotorV2 默认 Kp=4、Kd=15；之前测试脚本把 Kp 设为 12；速度/扭矩前馈默认零。既有左 J6 日志有停滞后跳动，不纳入本轮修复；自主抓放前必须单独验收跟踪性能。
- start_polling 在 MotorV2 实际是 200 ms 心跳，不是高频轨迹；失联和停发可能失去保持力。不能把 stop_polling、关闭进程或 disable 一律实现成“安全停止”。
- P7 构造/初始化路径可能确保并写入 P-T-M 模式；read_initial_state 在 V2 会发 Rest。此次绕过了这些具有状态副作用的路径。

### 3.2 上层运动能力的边界

本地 P7 源码有 get_angles/get_pose、FK/IK、move_j/move_p/move_l 等接口；API 存在不等于本轮已运行验收。move_j 有主机插值，move_p 有直接目标设置路径；都不能替代整机、桌面、手掌、相机及持物碰撞检查。URDF/FK 不能自动证明真实双臂安装外参、TCP、零位或限位正确。

## 4. 左右手接口

|项|右手|左手|
|---|---|---|
|SocketCAN|can0|can1|
|标准帧 ID|0x27|0x28|
|序列号|LHO6-04-276-R-Z-1-D|LHO6-04-322-L-Z-1-D|
|固件版本原始应答|C2 03 00 02|C2 03 00 04|
|六通道状态一次快照|80 7F 80 80 80 80|FE FF FE FE FE FE|
|协议身份|O6 / R|O6 / L|

版本字段按现有管理器可解释为 3.0.2 / 3.0.4，但保留原始字节为依据。两只手固件版本不同，后续动作及传感器功能应分别验收。

只读查询：C0=分片序列号、C1=PCB、C2=固件、C4=机械版本、01=六通道状态；33/35 为旧驱动中的温度/故障读取。没有响应的字段记为未证实，不把默认缓存当实测。完整应答见 evidence/can.json。六通道顺序（源码）为拇指弯曲、拇指侧摆、食指、中指、无名指、小指。六通道并不等于每根手指只有一个物理电机的完整硬件认证。

注意 01 单字节是读取请求；01 后跟六个值是动作命令，不能混用。原始 0–255、Python SDK 的 0–100 百分比和物理弧度是三套不同语义；不得把 JointState.position 惯例中的 rad 套到旧手驱动的原始数值上。手的开闭方向与抓取预设仍需实机标定。

补充只读结果：两只手 C1 均为 C1 03 00 00，C4 均为 C4 04 00 00；33 温度请求均有六通道回应，35 故障请求的六个通道均为 00。它们只是本次快照，不代表负载运动或热稳定验收。触觉选配及可用性尚未验证。存在触觉 API/配置 TOUCH:true 不构成有触觉证据；禁止依赖触觉完成抓取成功判定。

### 5.1 权限与访问方式

- 普通 qwer SSH 会话打开三机均报 usbEnumerator openUsbDevice failed。
- /dev/bus/usb/002/060、061、062 权限为 root:root 0664；qwer 不属 root 组，无写访问。临时 sudo 下 SDK 三机均能打开并取流，支持权限问题这一判断。
- 未安装/修改 udev 规则。后续应以设备组受限授权方式修复，重新用普通服务用户验收；不能把长期 root 运行作为生产方案。
- 现有 /dev/videoN 及部分 /dev/v4l/by-id 节点来自同一相机的多个视频/metadata 接口，不能按节点数量统计相机，也不能靠 videoN 永久绑定。
- 推荐以设备 SN 选择相机；USB 路径辅助核验。左右腕角色已通过现场逐台遮挡确认：左 AY6M8630086、右 AY6M86300GH；头部 CP2L863000KL 也已通过遮挡—恢复对照确认。禁止按枚举 index 猜左右。
- 相机硬件时钟不是 ROS/主机时钟。腕部图像必须建立时钟映射、epoch/reset 检测并对齐图像时刻的关节状态，不能直接取 latest TF。

## 7. 后续适配层应提供的接口（项目建议，尚未实现）

设备注册信息统一包含 role、serial、bus_path、protocol、source、verified_at、capabilities；未核验字段保持 null。
ArmState 使用关节名、rad、rad/s、接收与设备时间戳、有效位；HandState 显式标记 raw_u8 / percent；CameraObservation 包含 serial、profile、raw depth scale、frame_id、stamp、clock domain、K/D、配准状态及校准版本。
动作层应有 command_id、取消结果、actual_feedback、完成原因、timeout；发送成功不能当实际到位。
每条 CAN 总线只有一个运动命令所有者；诊断读取也必须受采样率与总线负载约束。
stop 接口返回已确认的停车/保持/失去保持状态，不能用一个模糊成功布尔值掩盖 V2 失联或手部停机能力未知。
