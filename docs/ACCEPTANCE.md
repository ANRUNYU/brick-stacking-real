# 阶段验收建议
下述次数与指标是研发建议，M0先共同冻结；不是官方赛规、设备保证或已完成实测。若需调整须在测试开始前记录原因，不能测试后换标准。

## 1. 真实动作前硬门槛
- 选侧/SN/CAN/关节顺序与设备匹配；另一侧有已验证的安全状态。
- 腕关节跟踪、限位/零位来源、TCP/安装/外参及环境碰撞模型已核实。
- 动作速度/加速度/误差/超时限制有来源；配置缺项则禁用。
- 物理急停、保持/停止/取消/失联的设备行为明确，现场人员与区域就绪。
- RGB-D空间配准与时间映射、关节/TF新鲜度门控已验证。
- 每次真机测试只一个动作所有者。Mock故障注入通过后，真实故障测试另行评估。
门槛未通过不妨碍离线代码合并，但不能开始真实抓放。暂缓修腕轴不代表绕过门槛。

## 2. 第一阶段（M3）
建议固定目标10次后，限定区域至少5个预先确定位置、共20次视觉抓放；不同位置涵盖工作区内可达点。位置范围、合格容差、静置时长和重试上限先配置。
建议起点：视觉抓放20次中至少18次首次完整成功；重试后结果另列，不掩盖首次失败。固定点/视觉点分别统计，任何人工扶正/补抓标为assisted；安全性问题零容忍，不因成功率达标放行。
每次成功须抓起、搬运、放稳、撤离复检全链成立；不可观测不计成功。物理XY/Z与倾斜偏差逐项报告，P50/P95附样本数。初始10mm/8mm等如采用只是研发目标，C须用误差预算评估可达性，不能当官方容差。

## 3. 第二阶段（M6）
建议先用人工搭建样本验证结构判定，再完成真实两层、最后完整四层。
建议冻结后做10轮完整自主试跑，以至少8轮完整十块成功作为首版研发起点；供料布局、照明条件、重试上限、任务时间上限及允许操作在测试前固定。时限必须待完整规则确定；暂缺时只记录耗时，不宣称满足比赛时间。
启动后正常流程不逐步等人工，人工介入的轮次单列，不计无人工完整成功。失败也记录已完成块数、层/色/支撑状态、倒塌、恢复次数与安全终止原因。
Mock/录包必须覆盖观测过期、颜色错误、同色混淆、抓空、放歪、遮挡UNKNOWN、支撑失效、倒塌、取消未确认及重启；不用未经评估的真实断连/断电来注入故障。

## 4. 每轮最少记录
run_id、commit、模式、配置与校准hash、设备身份、原始观测索引、目标block/slot、计划和执行ID、手状态、验证证据、时间、重试、人工介入和最终结果。
A交控制/反馈统计；B交感知/复检误差；C交坐标/路径/碰撞检查报告；D交手/FSM/恢复和整场汇总。每人修自己模块，失败难定位时共同看同一run_id。

## 5. 测试通过后仍需保留的边界
只验收一侧单臂；没有双臂避碰/交接/并发验收。相机角色绑定不等于外参通过；三台单独取流不等于三机并发通过。视觉/驱动API存在不等于运动能力已通过。
